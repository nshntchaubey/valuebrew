# Domain Research: Karnataka/Bangalore online liquor retailers — beer catalogue research for ValueBrew

**Research track:** `retail`

## Summary
I directly fetched (via curl, with a browser-like User-Agent) the homepages, robots.txt, sitemaps, category pages, and — where available — JSON API endpoints of madhuloka.com, livingliquidz.com, tonique.in, and three additional Bangalore/India liquor-delivery sites found via web search (beerbasket.in, onlinealcohol.in, livcheers.com). Madhuloka (Odoo/Odoo.sh commerce platform) has the richest, most Bangalore-relevant catalogue: ~1,603 product pages in its sitemap, a dedicated Beer category with ~103 SKUs across 6 paginated pages, a working `?search=` query parameter, and permissive robots.txt (Allow all, sitemap listed) with no Cloudflare/bot-challenge headers observed. It has no discoverable public JSON/REST/GraphQL product API — all attempted Odoo autocomplete/JSON-RPC endpoints returned 404. Living Liquidz is currently non-functional (HTTP 503 "app under development" on every URL tried, both www and non-www). Tonique.in is a WordPress/Elementor site with a single giant "Price List" page (a large HTML table, not paginated, not city-filtered despite claiming Hyderabad/Bangalore/Pune coverage) and exposes the standard WP REST API (`/wp-json/`) but no WooCommerce product endpoints were found — pricing data appears to be static/manually maintained HTML, last modified April 2023. Two additional WooCommerce-based retailers were found via search: onlinealcohol.in, which exposes a live, queryable WooCommerce Store REST API (`/wp-json/wc/store/v1/products` and `/products/categories`) returning structured JSON with price, images, and category (Beer category confirmed with 12 SKUs, ~241 total products site-wide per X-WP-Total header), and beerbasket.in, whose Store API categories endpoint works but products endpoint consistently 500-errors (likely a site bug, not deliberate blocking) — it also claims Karnataka-wide delivery (not Bangalore-specific) and has a large amount of low-value SEO "alcohol delivery in <city>" landing-page cruft. Livcheers.com (Next.js SPA) supports a Bangalore-specific URL and returned beer-related terms on a `?q=beer` search, but its data is client-rendered — no product JSON was found in the static HTML, so its catalogue depth/API is unverified. None of the six live sites showed clear Cloudflare challenge signatures in response headers during my fetches, though this does not rule out bot-detection under sustained/automated scraping.

## Sources
### Madhuloka (madhuloka.com)
- URL: https://www.madhuloka.com/
- Confidence: High
- Coverage: Full liquor range: Beer, Brandy, Gin, Rum, Vodka, Wine, Whisky, Absinthe, Liqueur, Sake, Tequila, plus Offers/Combo/New-Arrivals categories. Beer category verified at https://www.madhuloka.com/shop/category/beer-3 with ~103 unique beer SKUs across 6 pages (20/page, last page partial).
- Reliability: High for the pages actually fetched (all HTTP 200, consistent structure).
- Licensing: Unknown — no explicit terms-of-use for scraping observed; robots.txt does not disallow any paths.
- Automation Difficulty: Medium — no JSON/REST/GraphQL API discovered (tested /shop/autocomplete, /website/products/autocomplete, /shop/products/autocomplete, /shop/search as POST JSON-RPC — all returned Odoo's generic 404 page). Category and product pages are server-rendered plain HTML (Odoo eCommerce/website_sale module), so scraping is feasible via HTML parsing; pagination is path-based (/shop/category/beer-3/page/N) which is easy to iterate. Product detail pages carry schema.org microdata (itemprop=name/price/priceCurrency/offers) but no JSON-LD block.
- Refresh Frequency: Unknown/unverified — sitemap.xml (https://www.madhuloka.com/sitemap.xml) shows only one URL (contactus) with a <lastmod> (2024-10-14); product pages have no lastmod so freshness can't be confirmed from the sitemap alone.
- Recommendation: Best primary source. Crawl the sitemap.xml for the full product URL list (1,603 shop URLs observed, includes non-beer categories), then parse category pages (paginated, 20 items/page) and product detail pages (has price via itemprop=price/oe_currency_value, product name, image). Respect robots.txt (currently fully permissive) and set a reasonable crawl delay since no explicit crawl-delay is specified.
- Notes: VERIFIED: robots.txt fetched directly (https://www.madhuloka.com/robots.txt) = 'User-agent: *' with no Disallow lines, plus Sitemap directive. Server header = 'Odoo.sh' (confirms Odoo-hosted). No cf-ray or other Cloudflare headers seen in any response headers I captured, and requests without a User-Agent or with a plain curl UA returned normal 200 responses (no bot challenge observed) — but this is a limited sample, not a guarantee against rate-limiting at scale.

### Tonique (tonique.in)
- URL: https://tonique.in/price-list/
- Confidence: Medium
- Coverage: Single price-list page mixes multiple alcohol types (Beer, Whisky, Vodka, etc. all confirmed present as text) for what is nominally a Hyderabad/Bangalore/Pune-serving retailer per page title ('Tonique - Asia's Largest Liquor Boutique | Hyderabad | Bangalore I Pune'), but the fetched HTML showed no city-specific tabs/sections (only 4 occurrences of 'Hyderabad' as plain text, 0 of 'Bangalore'/'Bengaluru' in the body I fetched) — so it is unclear/unverified whether Bangalore-specific pricing is actually distinguished anywhere on this page.
- Reliability: Medium — page loads reliably (200) but content appeared to include placeholder/legacy text ('Price list coming soon') alongside real price rows (e.g. '₹400.00' next to 'Amsterdam Navigator Beer 500 Ml'), so trustworthiness of the live price data is uncertain.
- Licensing: Unknown, robots.txt is permissive (Allow: /).
- Automation Difficulty: Medium-High — the price list is one big static HTML <table> (633 <tr> rows found) embedded directly in a WordPress/Elementor page, not paged or filterable; no WooCommerce product API found (only default WP core/plugin REST routes — Akismet, Contact Form 7, Jetpack — were present at /wp-json/, no /wc/ namespace). Scraping means parsing one large HTML table.
- Refresh Frequency: Page shows dateModified 2023-04-10T07:29:08+00:00 in its Yoast JSON-LD schema and og:description text 'Price list coming soon' — suggests this page may be stale/placeholder as of my fetch.
- Recommendation: Low-to-medium priority; usable only as a supplementary/cross-check source given uncertain freshness and lack of Bangalore-specific structure. Re-verify before relying on prices.
- Notes: VERIFIED: robots.txt fetched at https://www.tonique.in/robots.txt = 'User-agent: *, Allow: /, Sitemap: https://tonique.in/sitemap_index.xml'. Sitemap index (https://tonique.in/sitemap_index.xml) contains only one sub-sitemap (page-sitemap.xml), consistent with a small, mostly-static WordPress site. Homepage headers included a Cloudflare-Turnstile-related Permissions-Policy header (mentions challenges.cloudflare.com) but no cf-ray header — inconclusive on whether Cloudflare actively fronts the site.

### Online Alcohol (onlinealcohol.in)
- URL: https://onlinealcohol.in/wp-json/wc/store/v1/products?category=20
- Confidence: High
- Coverage: Full liquor range via WooCommerce categories (verified via GET https://onlinealcohol.in/wp-json/wc/store/v1/products/categories): Beer (12), Champagne (5), Cigarettes (6), Gin (19), Red Wine (7), Rum (18), Tequila (10), Vodka (35), Whisky (89), White Wine (1), Wine (63), Uncategorized (3) — beer is a small fraction of total catalogue. Has a Bangalore-specific landing page (https://onlinealcohol.in/online-alcohol/bangalore/, verified reachable, title 'Online Alcohol Bangalore | Liquor Store Bangalore', mentions Beer/Vodka/Whisky in body text).
- Reliability: High for the calls made — consistent 200s, well-formed JSON, X-WP-Total/X-WP-TotalPages headers present for pagination.
- Licensing: Unknown — no explicit API terms observed; robots.txt (fetched at https://onlinealcohol.in/robots.txt) disallows only WooCommerce log/transient/upload paths and add-to-cart query strings, does not disallow /wp-json/.
- Automation Difficulty: Low — genuine structured JSON API confirmed: GET /wp-json/wc/store/v1/products/categories and /wp-json/wc/store/v1/products?category=<id>&per_page=<n> both return clean JSON (id, name, slug, permalink, prices.price/currency_code, images, etc.). This is the easiest catalogue to automate against of all sites checked.
- Refresh Frequency: Unknown/unverified — no lastmod data checked; homepage response showed 'age: 156578' and 'x-hcdn-cache-status: HIT' (Hostinger CDN cache), suggesting the homepage itself may be served from a long-lived cache, but the JSON API responses I hit were not going through that same cached path (200 fresh responses, X-WP-Total header present).
- Recommendation: Strong secondary/complementary source specifically because it has a real, low-friction JSON API — good for cross-validating prices/SKUs found on Madhuloka, though its beer selection (12 SKUs) is much smaller than Madhuloka's (~103).
- Notes: VERIFIED directly: categories endpoint and beer-category products endpoint both fetched and parsed successfully in this session. Page also carries heavy ad-network script tags (profitablecpmrate.com, adclickppc.com, highperformanceformat.com) suggesting a lower-quality/ad-monetized site — treat brand/price data with correspondingly lower trust than Madhuloka.

### Beer Basket (beerbasket.in)
- URL: https://beerbasket.in/type/domestic-indian-beer/
- Confidence: Medium
- Coverage: Claims delivery in 'Chattisgarh, Delhi, Haryana, Jharkhand, Karnataka, Maharastra, Odisha & Punjab' per homepage text, and has a dedicated /liquor-home-delivery-in-karnataka/ page (verified reachable, 200) — but I did not find explicit Bangalore-city text within the fetched Karnataka page body, so Bangalore-specific coverage (vs. state-wide/other-Karnataka-cities) is an inference, not confirmed. Beer taxonomy verified at https://beerbasket.in/type/domestic-indian-beer/ (16+ SKUs on one page incl. Kingfisher variants, Budweiser, Carlsberg, Corona, Foster's) — the /product-category/beer/ URL 301-redirects to an image file (broken Yoast redirect), so the taxonomy is filed under /type/ not /product-category/.
- Reliability: Medium — category HTML pages reliable; JSON product API unreliable (broken).
- Licensing: robots.txt (fetched at https://beerbasket.in/robots.txt) disallows some WooCommerce query-string variants (?add-to-cart=, ?orderby=, ?filter=, price range params) and /wp-admin/, allows admin-ajax.php; does not disallow /type/ or /product/ paths or /wp-json/.
- Automation Difficulty: Medium — WooCommerce Store API partially broken: GET /wp-json/wc/store/v1/products/categories works (200, returns Beer category id=136 with description), but GET /wp-json/wc/store/v1/products (with or without category filter) consistently returned HTTP 500 (WordPress error page) across 3 repeated attempts — this looks like a server-side bug/misconfiguration on their end rather than deliberate API blocking, since the sibling categories endpoint works fine. Fallback is HTML scraping of /type/<slug>/ taxonomy pages, which do render full WooCommerce product loops with prices.
- Refresh Frequency: Unknown/unverified.
- Recommendation: Lower priority than Madhuloka/Online Alcohol — site has significant low-quality SEO cruft (dozens of near-duplicate '/alcohol-delivery-in-<city>' pages including many US city names like Alexander-City, Anniston, Auburn — suggesting a template mill rather than a curated retailer), and its own product JSON API is broken. Useful only as a tertiary cross-check for beer SKU names/prices.
- Notes: VERIFIED: 500 error on Store API products endpoint reproduced 3 times in this session (not a one-off transient failure within my test window, but I cannot rule out it being intermittent over a longer period).

### Livcheers (livcheers.com)
- URL: https://www.livcheers.com/bangalore
- Confidence: Low
- Coverage: Homepage/Bangalore page text mentions 'Beer' (6x) and 'Kingfisher' (3x/4x case variants) confirming beer is part of the catalogue, and a city-scoped URL pattern (/bangalore) is confirmed to return a Bangalore-titled page (verified: title tag includes '| Bangalore'). However this is a Next.js client-rendered app — no product JSON, price data, or catalogue structure was visible in the static HTML I fetched (data likely loads via client-side JS calls to an API not observable through a plain curl fetch).
- Reliability: Cannot assess catalogue reliability without seeing real product data.
- Licensing: robots.txt explicitly disallows /admin, /dashboard, and /api/ for all user agents, and fully blocks a long list of named SEO/scraping bots (SemrushBot, AhrefsBot, MJ12bot, GPTBot, Bytespider, CensysInspect, etc.) — a clear, explicit signal that this operator does not want automated crawling of any kind.
- Automation Difficulty: High (as directly observed) — static HTML fetch shows only Next.js chunk script tags, no embedded product data or __NEXT_DATA__ JSON blob was found in the page I retrieved; would require a JS-executing fetch or reverse-engineering underlying API calls (robots.txt disallows /api/ for all bots, fetched at https://www.livcheers.com/robots.txt), which is a real obstacle even if endpoints were found by other means.
- Refresh Frequency: Unknown.
- Recommendation: Not recommended for automation given explicit /api/ disallow and the extensive bot-blocklist in robots.txt — pursuing this further would mean disregarding the site's stated crawling policy.
- Notes: VERIFIED: robots.txt content fetched directly and quoted above. Served via BunnyCDN with 'x-livcheers-agent: livcheers' custom header — a bespoke Next.js commerce app, not WooCommerce/Odoo.

## Key Findings
- Madhuloka is the strongest ValueBrew source: ~1,603 sitemap-listed product URLs, a browsable Beer category (~103 SKUs, 6 pages of 20/page via /shop/category/beer-3/page/N), a working ?search= query parameter, fully permissive robots.txt, and no bot-challenge signatures observed — but it exposes no discoverable JSON/REST/GraphQL product API (all tested Odoo autocomplete/search endpoints 404'd), so extraction must be HTML scraping.
- Onlinealcohol.in unexpectedly offers the best-quality structured API of any site checked: a live, working WooCommerce Store REST API (/wp-json/wc/store/v1/products and /products/categories) returning clean JSON with prices, images, and category IDs — verified live in this session — though its Beer category is small (12 SKUs) versus ~241 total site products (mostly whisky/wine/vodka).
- Living Liquidz is completely non-operational right now (HTTP 503 'under maintenance' on every URL/robots.txt path tried, both with and without www) and cannot be used as a source in its current state.
- Tonique.in's price list is a single, large static HTML table (633 rows) on one page, dated April 2023 in its schema.org metadata and containing an apparent leftover 'Price list coming soon...' placeholder phrase — its currency/freshness should be treated with caution, and no Bangalore-specific pricing structure was found despite the site's branding claiming Bangalore coverage.
- Beerbasket.in's WooCommerce Store API categories endpoint works but its products endpoint returns HTTP 500 consistently (reproduced 3x) — likely a site bug rather than deliberate blocking — so HTML scraping of /type/<slug>/ taxonomy pages is the only reliable extraction path there; the site also has heavy low-quality '/alcohol-delivery-in-<city>' SEO landing pages including many unrelated US city names, which weakens confidence in its overall data quality.
- Livcheers.com explicitly disallows /api/ and blocks a long, named list of scraping/SEO bots in its robots.txt — a clear signal against automated collection — and its catalogue is client-rendered (Next.js) with no product data visible in raw HTML, making it both technically hard and policy-discouraged to scrape.
- No site checked showed unambiguous Cloudflare bot-challenge headers (cf-ray, cf-mitigated, etc.) in the responses I actually captured; Tonique's headers referenced Cloudflare Turnstile in a Permissions-Policy string but that alone doesn't confirm active challenge protection, and this was tested only with modest, low-volume requests, not sustained scraping.

## Risks
- All 'no Cloudflare/bot protection observed' conclusions are based on a small number of polite, low-rate requests within a single session — sustained or high-volume scraping could trigger protections not visible in this test.
- Sitemap-derived counts (e.g., Madhuloka's 1,603 product URLs, ~103 beer SKUs) are point-in-time snapshots from this session's fetch and will drift as catalogues change; no long-term update-frequency signal was found (lastmod dates were absent almost everywhere).
- Tonique's price-list content could not be confirmed as current/accurate — it contains an apparent stale placeholder phrase and a 2023 modified date, so any prices pulled from it should be flagged low-confidence until corroborated elsewhere.
- Living Liquidz's outage status is only confirmed for this session; it may come back online later, so this finding should be periodically rechecked rather than treated as permanent.
- Livcheers' robots.txt is an explicit statement of crawling policy; scraping its /api/ endpoints (even if discoverable) would go against the site's stated wishes and carries higher legal/ethical risk than the other sites reviewed.
- Beerbasket's broad claim of 'Karnataka' delivery was verified only at the state level (a /liquor-home-delivery-in-karnataka/ page exists); explicit Bangalore-city confirmation within that specific page's body text was not found, so treat Bangalore coverage there as unconfirmed/inferred rather than verified.

## Unverifiable / Blocked
- Could not find any hidden/internal JSON, REST, or GraphQL product API on madhuloka.com despite testing several plausible Odoo endpoint paths (/shop/autocomplete, /website/products/autocomplete, /shop/products/autocomplete, /shop/search) — all returned Odoo's generic 404 page, so I cannot confirm one exists or definitively rule it out (there could be an endpoint I did not guess correctly).
- Could not confirm actual update/refresh frequency for any of the six sites — none of the sitemaps or pages I fetched carried reliable per-product lastmod timestamps.
- Could not verify Living Liquidz's catalogue, robots.txt content, API structure, or bot protection because the site returned HTTP 503 on every path tried; nothing about its normal operating state could be assessed.
- Could not verify Livcheers' actual product catalogue structure, pricing, or any API shape because its data is loaded client-side via JavaScript not visible in a plain HTML fetch, and its robots.txt explicitly disallows /api/, which I did not attempt to bypass.
- Could not confirm whether Tonique's price-list page is manually updated per city (Hyderabad vs Bangalore vs Pune) since no city-selector markup was found in the fetched HTML — it's unclear if this single table is meant to represent one city's prices, an average, or is simply outdated/generic.
- Could not determine why beerbasket.in's Store API /products endpoint fails with HTTP 500 (server logs are not accessible to me) — labeled as likely a bug based on the categories endpoint working fine, but this is inference, not confirmed root cause.
- General web search (via the internal search tool) failed with a token error, so the list of 'other Bangalore/Karnataka retailers' relies on a single external WebFetch-based search rather than a broader survey; there may be other relevant retailers not surfaced by that one query.
